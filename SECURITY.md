# Security reporting

Do not report vulnerabilities, credentials or private data in public issues.

If the affected repository enables private vulnerability reporting, use its Security → Report a vulnerability page. Otherwise contact the repository owner through an established private channel to arrange secure reporting before sharing sensitive details.

Include the affected component, impact, reproduction steps and relevant version. Use sanitized evidence. If a credential was exposed, revoke or rotate it immediately through its issuer; removing it from a file is not sufficient.

Supported fixes target the current maintained version unless the repository documents a different support policy.
