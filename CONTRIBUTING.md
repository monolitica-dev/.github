# Contributing

Read the repository README and AGENTS.md before changing code. Follow existing conventions, use the pinned package manager and keep changes focused.

Create a branch, add meaningful tests for behavior changes, run documented checks, and open a pull request. Wait for CI and automated review, address valid findings, and request human review. Do not merge known failures or use review scores as a substitute for judgment.

Never commit real environment files, credentials or sensitive customer data. Use the approved secret manager. Document configuration changes using names and empty values only. Report security concerns privately according to SECURITY.md.

Authentication, authorization, billing, infrastructure, migrations and public API changes require careful human review. Use concise English commits without attribution trailers. Do not force push or rewrite shared history without agreement.
